# Legacy connect selectors must preserve their route

The existing `quick_enabled` expression treats every invocation without a technical `--profile` as Quick Connect. That changes the established interactive canonical-catalog and multi-harness flows even when the caller explicitly uses legacy selectors. These users can be routed into a public-ID setup instead of observing an existing binding or recovering the retained legacy intent.

The derivative changes only `cli/connect.py`. An explicit public entry (positional harness, positional project name, or `--id`) selects Quick Connect. Without public syntax, these legacy selectors preserve the existing route: `--profile`, `--project`, `--client`, `--agent`, `--new-agent`, `--name`, `--workspace-id`, `--binding-id`, `--candidate-ref`, `--provider-home`, `--operator-profile`, `--remote-draft`, `--setup-receipt-output`, `--approve`, `--new-connection`, and `--review-current`. A bare invocation and operational flags such as plan/JSON/no-chat/timeout/start-at-login retain the new basic entry. Service configuration flags continue to identify the service rather than supplying a new public entry.

The existing exact-profile checkpoint read remains intact: a retained Quick checkpoint selects its original flow after the profile has been read. Public syntax takes precedence over legacy options so `connect codex --project ...` and `connect --id reviewer --profile retained` remain explicit Quick entries. No identity, authorization, setup, receipt or profile format is changed.

The isolated derivative passed **35 tests**: 28 parser/route cases, four actual Quick `prepare` route fences (including a retained Quick checkpoint), and the three original HTTP/SQLite scenarios requested by Root. The original nodes are `test_cli_existing_canonical_without_profile_creates_only_shortcut`, `test_single_observed_harness_needs_no_profile_and_existing_connection_offers_all_intents`, and `test_two_distinct_harnesses_share_project_keep_custom_a_and_recover_b_finish`. Their assertions retain the canonical binding, shared project, custom identity/settings, grant invariants, lost-Finish recovery, and cancellation guards. The original test files are copied byte-for-byte without patching their expectations. Provider/lifecycle boundaries in these existing fixtures are explicitly synthetic; no real harness was invoked.

`legacy-gate-derivative/changes.patch` is **not applied** to the repository or installed candidate. The qualified 0.3.6 Python loaded a full disposable package overlay with this one product-file change, with no checkout source path; Core and Connector remained installed. All four cuts exited zero normally; no signal or force was used, and all observed owned processes were physically absent. All 1,027 installed Nexus/Core/Connector payloads and the 45 copied repository fixture/data inputs retained their initial bytes.

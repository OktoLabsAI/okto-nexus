# SI-019 exact Codex presentation reads

The authorized Windows peer test was repeated with redacted field-shape capture. Codex 0.170.0 sent `thread/read` with the exact UUID. Its `thread/resume` request used the exact UUID and `excludeTurns: true`. All 15 optional override values were null. The frontend still rendered the synthetic history and the probe observed the process and transport exit.

The internal request parser recognizes these two method shapes. It returns a typed read or view initialization intent, with a flag for reading turns. It requires the complete, canonical UUID already selected by the owner. It rejects aliases, sibling IDs, extra fields, and non-null context overrides. View initialization uses a distinct internal intent with no native resume method attached. Engine discovery and productive methods have no route through this parser.

The parser and broker passed 31 focused tests. Ruff and strict Twine checks passed. The wheel module matches the source byte for byte.

The follow-up covers the frontend's two required page requests. The parser accepts only the exact thread, the supported sort directions, at most 20 turns or 100 items, and bounded opaque cursors. It rejects inline item anchors, unrestricted turn item expansion, and deferred output requests. A supplied turn UUID and cursor still require validation against the current history and presentation before reading. Parser tests passed 37 cases.

The history source reuses the authorized canonical event reader and verifies the exact owner generation, binding, workspace and stream. It captures one contiguous event position and pages written turn states and completed text items without transferring native cursors or exposing private native fields. Cursor signatures are scoped to the capture, page kind, direction and optional turn. Tests verify both page directions, cursor isolation, wrong generation and sibling turn rejection, text sanitization, gap handling, and refusal beyond 512 events or the canonical replay byte budget. Unsupported items are counted and excluded. This initial source covers bounded committed text history and does not provide live deltas or an unbounded replay. Larger sessions and additional item kinds require qualification before exposure.

The history, parser and broker regressions passed 57 tests. Strict Twine checks passed and the wheel contains the history source byte for byte. An authorized native Windows probe used these page functions with an empty fixture snapshot and one real ephemeral idle thread. The Codex 0.170.0 viewer requested five turns in descending order with `itemsView: notLoaded`, and 100 items in descending order across the thread. The viewer rendered the session and exited while the same thread remained readable on the same owner. That probe exercised the exact native page requests against an empty snapshot. The SQLite projection, populated pages and cursor checks are covered by the synthetic tests.

The internal history channel now joins an active attachment to the exact owner proof and canonical snapshot. It authorizes and checks the owner before and after constructing each page. It keeps the first successful capture for that channel so the two catalogs share one committed position. The SQLite presenter test verifies refusal of a sibling thread, revocation during capture and replacement of the runtime owner between pages. The history, parser and broker regression passed 58 tests, and both package archives passed strict validation.

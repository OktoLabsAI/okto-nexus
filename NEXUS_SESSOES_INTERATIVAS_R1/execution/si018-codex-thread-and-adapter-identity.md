# SI-018 separate Codex thread and Core adapter identity

The copied Core adapter retains its internal session identifier in the opening receipt. Codex reports its separate thread UUID in the Core-originated configuration event. Earlier synthetic control tests reused one ID for both. Nexus now preserves the receipt ID for owner proof and requires the UUID from the single, intact, committed configuration event in the exact session epoch for Codex turn controls. The capability revision includes the configuration event hash. An absent, ambiguous, corrupt or uncommitted observation does not select a target.

Core `566f02349caa861abafd8cc600abc69d1d7d8a75` adds a typed host entry point for reading metadata from the assigned Codex thread. It makes one `thread/read` request with `includeTurns: false` on the existing transport. The adapter checks registration before and after the read and reduces the response to the exact ID, timestamps, state and ephemeral flag. It shares concurrent reads for the same session and keeps the pending read alive across presenter cancellation. Core checks the current owner and process evidence both before and after the read.

The embedded dispatcher obtains its UUID from the retained event and revalidates the Server lease, mapping and exact runtime after the Core call. Connector `1c449e211a5bb62b0fff128400f39e610fa58ea3` uses its exact registered runtime for the same read.

# SI-015 versioned session command catalogue

The dashboard can read the catalogue under the human operator login and the exact session scope, including its owner generation. Version 1 declares a fixed set of action IDs, effects, arguments, handlers, surfaces, states, reasons, and confirmation requirements. Help and status are Nexus reads. Send uses the existing next-turn capability and productive grant. Steer and interrupt project the current exact Codex target, with the applicable queue barriers. A documented native resume entry has no dashboard handler and makes no claim about the command being present on the selected installation.

The revision covers the exact scope, declared effects, current capability and target evidence, productive grant, and agent revisions. The read does not consume the grant, create a human authority reference, or start an operation. Literal slash input remains unavailable. Native content and extensions cannot add commands to the fixed declarations.

## Evidence

- The session interaction and runtime regression suites passed 95 cases. The synthetic Codex integration verifies signed-in exact reads, stale-generation refusal, a stable revision for unchanged facts, a revision change at turn start and completion and after an agent configuration change, label and source metadata, denial of an undeclared request, and absence of native sends before normal turn admission. The same integration exercises the existing steer and next-turn endpoints.
- Focused Ruff, Git diff checks, and offline package builds passed. The wheel and source archive passed strict Twine checks.

## Delivery and rollback

The catalogue is a read-only dashboard endpoint. This increment has no storage migration or Core or Connector pin change. Rolling back removes the catalogue endpoint and preserves the prior canonical interaction paths. SI-015 remains in progress. Typed command invocation, revision enforcement during command admission, the Home picker, and cross-harness qualification still need evidence. No literal test case is promoted.

## Revalidação no pacote instalado

O Edge recebeu o catálogo v1 da sessão exata de um app-server Codex
0.157.0, aberto pelo Connector neste Windows. A versão da abertura veio
do registro canônico. O catálogo distinguiu a consulta `status` do Nexus
e `resume` exclusivo do terminal. Pausar a fila por outro cliente
avançou a revisão e tornou a reorientação indisponível. A revisão antiga
recebeu HTTP 409 e preservou o rascunho. Uma nova confirmação gravou
exatamente uma entrada pendente.

Após a conclusão do turno original, o Edge exibiu seu resultado e
manteve a entrada retida. Uma alteração isolada nos metadados do agente
mudou a revisão de configuração. A consulta de status pela revisão
antiga recebeu HTTP 409 e pela atual recebeu HTTP 200 na mesma sessão.

Passaram 31 regressões do pacote instalado, o ensaio no Edge e a
auditoria do SQLite. A primeira rodada chegou ao recibo terminal antes
da projeção do resultado. O roteiro repetido aguardou a projeção da
operação exata. O modelo foi simulado em loopback. A matriz do SI-004
fundamenta a seleção por versão e conserva seus cenários de campanha
pendentes. O marco é reversível pelo commit e dispensa migração.

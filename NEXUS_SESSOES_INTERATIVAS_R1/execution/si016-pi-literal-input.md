# SI-016 e SI-039 · Texto literal e qualificação do Pi

No Pi 0.87.1 com Node 24.15.0 no Windows, o RPC padrão ignorou `expandPromptTemplates: false`. Ele expandiu uma skill e um template e executou um comando registrado pelo fixture. A API de sessão do Pi respeitou a opção. Na mesma sessão, o provedor simulado recebeu os três textos originais uma vez cada, incluindo espaços finais e Unicode, sem expansão nem execução do comando. Um segundo perfil incluiu um handler `input` e comprovou que ele ainda pode reescrever a mensagem mesmo com a expansão desativada.

Um ensaio separado usou o host RPC revisado do Core. O observador do fixture roteou uma entrada tipada para a chamada nativa com expansão desativada. O ensaio preservou os três textos, o ID da sessão e o envio comum. A entrada malformada e o perfil que registrava um handler `input` receberam recusa antes de iniciar um turno. A recusa preservou a sessão e permitiu enviar o próximo texto comum. [Fixture da API nativa](fixtures/pi_literal_probe.py) [Fixture do host RPC](fixtures/pi_literal_guard_probe.py)

O inventário instalado comparou o Pi 0.87.1 com o Pi 1.5.2 selecionado na instalação local. O Core qualificou o 0.87.1 para o renderizador revisado, a interrupção e a reorientação. O 1.5.2 permaneceu sem essa qualificação e sem controles qualificados. O estado de inventário `READY_FOR_RUNTIME` mantém a instalação elegível para avaliação de protocolo. A comparação leu os artefatos do 1.5.2 sem iniciar essa versão. [Fixture da comparação](fixtures/pi_installation_inventory_probe.py)

Os dois ensaios nativos usaram perfis descartáveis, permissões de acesso limitadas no processo Node e um provedor simulado em memória. As 23 regressões instaladas do contrato de sessão e da API passaram. As primeiras rodadas do RPC exigiram ajustar o diretório descartável para o Pi encontrar os recursos do projeto dentro da área permitida e carregar a extensão de teste. [Resultados, comandos e hashes](si016-pi-literal-input.json)

SI-T-D06 permanece aberto. O experimento ainda precisa de uma intenção explícita de texto literal no Nexus, persistida na fila e encaminhada sem conversão ao host exato. A admissão e o despacho precisam revalidar a capacidade, com recusa antes de qualquer entrega quando houver interceptação possível. SI-T-I06 também continua com a etapa de campanha em aberto. A mudança deste marco acrescenta fixtures e evidências, com reversão pelo commit e sem migração.

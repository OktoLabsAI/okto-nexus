# SI-030 terminal session selection

`okto-nexus session list --id ID` resolves the public Harness ID inside the authorized workspace. Local invocations can resolve a unique registered workspace from the project folder. `--workspace-id` selects an exact workspace, including through a saved remote operator profile. Existing project profiles remain available through `--profile`. The command reads canonical session pages for the verified binding and reports whether the bounded list is complete. It rejects mismatched workspace realizations and nonadvancing cursors.

`session attach --id ID --session-id SESSION` reads the exact session and current owner generation. With multiple candidates, the TTY asks which one to inspect and reads that session again before review. JSON and non-TTY invocations return a structured refusal or selection requirement. An unavailable exact session is refused. No selection calls Connect, opens an engine, sends work or recovers a pending submission. `work resume` retains its receipt-recovery behavior.

The new local review checks the operator login, owner and attachment capability and returns the exact generation and capability revision before an attachment ticket is issued. The viewer client verifies the known Windows x64 Codex binary, uses a temporary profile and project, and supplies only the relay bearer to the child. Closing it ends its presentation link. Nexus reports the nonsecret attachment ID and launches the native executable directly.

# SI-004 Windows Codex viewer and a real ephemeral owner

The operator approved a disposable Codex 0.170.0 app-server probe without inference. The executable matched the same pinned SHA-256 as the frontend-only test. The engine and viewer ran in separate empty temporary profiles and projects, with provider credentials absent and proxied requests directed to a rejecting loopback peer. The app-server listened on stdio. The fixture opened one ephemeral idle thread without a prompt and passed its exact UUID to the viewer using an authenticated loopback WebSocket.

The prototype reused the Nexus presenter read parser for `thread/read` and `thread/resume`. Only `thread/read` crossed from the viewer bridge to the app-server. The bridge formed the view initialization reply from the original opening metadata and current exact thread. The app-server received one `thread/start` from the test owner before the viewer connected. The viewer never received that capability.

The first two runs identified additional required history reads. The viewer stopped while loading the first history page if `thread/turns/list` was refused, and then stopped on `thread/items/list` if it could read only the turns page. The successful run returned local empty pages for the known empty fixture thread. The viewer requested limits of 5 turns and 100 items. An attempted owner `thread/read` with `includeTurns: true` on this ephemeral thread returned error `-32600`. The successful continuity check used metadata reads. Production paging with content still needs a bounded source of authorized history.

The successful run rendered the session, then the fixture terminated only its launched viewer. The peer observed the disconnect and the still-running original app-server answered for the same thread ID, session ID, working directory and idle state. Closing the engine's own stdio afterward returned exit code 0. The engine received no turn, approval or tool request. The proxy sink rejected five connections during startup and observation. [Sanitized wire observations](si004-codex-ephemeral-owner-windows.json)

This proof covers the installed frontend and app-server with an empty, idle, disposable thread. It leaves Core-managed ownership, active work, populated history and paging, product authorization, saved resume, Connector transport, and Pi and Claude integrations open. It changes no product behavior and does not qualify any production capability.

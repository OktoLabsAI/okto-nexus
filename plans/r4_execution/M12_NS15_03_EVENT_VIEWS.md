# NS15.03 canonical event reads — October 1, 2026

MCP `harness_event_list`, the existing harness REST event route and the R4
runtime session event route now share an authorized canonical history reader.
Authentication and event selection share one read transaction. Actor, subject
and operator authority follow session reads; executor and stream epoch remain
explicit namespace selectors. Closed sessions retain readable history.

Pages expose original Core event fields with receipt time, scope, epoch,
contiguous watermark, gap state and continuation cursor. Only committed
contiguous events are visible. Count and payload byte limits bound each page;
stored hashes and namespace/sequence checks reject corrupted history. Events
above a gap remain hidden until ingress closes that gap. Duplicate ingress
does not duplicate the public history.

Canonical reads never instantiate the legacy harness service. Legacy sessions
retain their existing response and authorization. This migration introduces
no automatic domain broadcast: the existing production journal path publishes
to subscribers, and its compatibility-only notable-message branch is not a
canonical publication contract.

Installed evidence is generated by `run_ns15_03_event_views.py` and recorded in
`test_runs_20261001_ns15_03_event_views.json`. Public adapter tests cover scoped
reads, closed history, malformed cursors, bounded pages and corruption. The
gap test uses authenticated ingress with an isolated session-view stub;
authorization is verified separately through the public adapters. Native peers
and readiness remain fixture-local, not real provider or remote qualification.
Two legacy attach tests are POSIX-only and skipped on Windows; they are excluded
from the passing-test count.
The initial legacy campaign exposed two stale REST fixture expectations:
attach denial now explicitly disables the feature, and per-call backend input
expects the existing validation refusal. Initial logs/XML are retained under
`ns15-03-event-views-initial-*`; the resume runner reuses the same installed
wheel and reruns legacy/architecture checks after these test-only corrections.

Combined claim competition, context-only observation, remaining subscriber
parity audit, cross-protocol failure fallback, canonical capture retention,
native loader removal and final restore/release acceptance remain pending.
TR4-06-05/TR4-15-03 and release gates remain open.

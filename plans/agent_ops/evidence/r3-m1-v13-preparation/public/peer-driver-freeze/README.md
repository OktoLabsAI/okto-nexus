# Successor13 root-driver candidate

Offline candidate only. Ten pinned runtime files; no receipt, real controller,
service, HTTP request, provider call or authentication was created while preparing
this directory. The previous v12 bundle and its campaign remain unchanged.

`ROOT` is the retained v12 bundle ownership boundary. `CONTROL`, `PUBLIC` and
`PRIVATE` belong to `ROOT/successor13`. New evidence, control checkpoint and outer
invocation records use successor13 paths. Preparation protects only the new private
directory and these drivers' runtime outputs, never old homes. Revision13 receipts
must bind both roots, proposal SHA, policy and ancestry. The receipt is a technical
binding of standing human authorization, not a claim the user quoted a proposal SHA.

Finite sequence, using the installed pinned Python with `-I -B`, the final proposal
SHA and technical receipt SHA on every invocation:

1. `invoke.py <common arguments> lifecycle initialize`
2. `prepare_observation.py <common arguments>`
3. `invoke.py <common arguments> lifecycle nexus install`, then `nexus start`.
4. `invoke.py <common arguments> adopt_local once`. Exact predecessor profile pins
   are checked only here. Canonical binding/me reads and the stable ready owner
   precede creation of a new controller carrying admissions8/tokens111651. No setup
   dispatch, native journal reset, model reservation or prior checkpoint mutation.
5. `invoke.py <common arguments> authorize_local review`. Installed `run_work`
   parser/handler performs one read-only review POST while normal accounting runs.
   A sole available unused20 grant is reported without issuing another. A sole
   expired unused20 grant can be explicitly selected for replacement. Other states,
   additional grants, changed scope/actions or durable pending issuance are refused.
6. For an expired grant only, root writes the reviewed selection to
   `PRIVATE/authorize-local-reviewed.json`: ordinary driver tags plus
   `decision: "issue"`, `review_sha256` (raw public review file SHA), and
   `review_revision` (canonical review hash). Then select
   `invoke.py <common arguments> authorize_local apply` once. Installed CLI owns
   recover/CAS issue and request checkpointing; transport permits at most one of
   each, forbids unrelated POSTs and does not replay lost responses. Limits remain
   60minutes/20actions, with the same five original actions and identity scope.
7. The local useful-work wrapper calls `require_local_work_authorization(X)` before
   admission. It verifies adoption/review/replacement evidence and requires at least
   240seconds remaining by the local wall clock. This is a prospective window check,
   not proof of enforcement or a guarantee of two work successes. It never infers
   canonical expiry, renews automatically or runs a second review. A short available
   window is an explicit refusal requiring reconciliation outside this finite run.

Subsequent work/remote steps retain the finite wrapper choices. No `setup` or
`local_plan` selection exists. Root drivers use controller policy/summary; they do
not add a second token counter. Policy threshold is supplied by the frozen13
controller (preventive500000/tolerance700000, new4/cumulative12, deadline120).

Cleanup remains normal stop, retained physical PID/birth/generation exit proof,
exact drain, uninstall and positive canonical final absence. The Connector that
was never selected can be proven absent after local work and operator login only
with a complete finite local-only invocation ledger, closed predecessor pin,
empty Connector home, no remote effect markers, local-only sealed accounting and
two stable inventory/checkpoint observations around canonical absence. An installed
Connector after local work still requires physical reconciliation: the inherited
install-only proof intentionally remains strict and does not invent PID exit.

The old v12 local failed-setup exception has been replaced, not used as evidence of
successor absence. Unknown/incomplete wrapper effects refuse closure. Final closure
keeps faults and observed accounting; it does not promote plan acceptance.

Tests use synthetic homes/HTTP/processes and the installed CLI parser and
TerminalAuthorization implementation. Runtime sources are never invoked against
real services during qualification. Fixture directories, authentication-shaped
synthetic files and captured fixture stdout are excluded from the public allowlist.

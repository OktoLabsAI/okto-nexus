# PR-09 — optional Herdr observer and publishing helper

PR-09 is implemented and qualified for the scope below. This record does not close remaining R3 provider/client/service campaigns, PR-10 or the complete plan. Nexus remains `0.3.3` on `feature/v0.3.3`; Connector/Core are unchanged.

## Delivered behavior

`okto-nexus observe herdr bind` reads the selected local process and previews a selection hash covering its identity and the exact Nexus source/instance/generation/destination. Repeating with the explicit hash saves the binding without publishing. `run` requires an independently issued `nxobs_` credential in a named environment variable. `status` reads the local journal without contacting Herdr or publishing. No Server, Connector, executor, MCP facade or plugin daemon is started by the observer.

The qualified source is Windows x64 Herdr **0.9.5**, protocol **22**, schema version **1**. The adapter verifies the installed binary's bundled schema, then checks the live version/protocol/compatibility. Its complete command allowlist is version, schema, Server status, session snapshot and pane process-info. It excludes terminal reads and `agent.explain`, which can include screen text. Child arguments have no shell interpolation; output and elapsed wait are bounded, credentials and ambient Herdr routing are excluded, and diagnostics contain fixed codes.

A binding combines an explicit installation namespace/session/location/terminal, approved executable image, local host hash, PID and creation FILETIME. A live Windows process handle brackets source metadata reads. The optional logical agent-session ID contributes a hash but is never the sole proof. Names are aliases. Moves, missing/replaced occupants, changed identities or regressed counters require reassociation. Shells, known wrappers, remote processes and unqualified platform/version contracts are refused.

All projected Herdr activity uses `inferred`, since the metadata-only API does not establish reported-state authority. `done` becomes idle; the initial snapshot only establishes a completion baseline. A later coherent `completion_seq == state_change_seq` can produce a stable observational completion reference. Repeat reads do not change Herdr's seen/focus state or conclude Nexus work.

The helper performs one origin-bound HTTP POST, validates reports and matching receipts, and never renews credentials or retries automatically. The journal reserves the full report and sequence before transmission. Explicit retry sends that exact historical payload, including its original observed timestamp. Incompletely received results remain uncertain across later refused retries; every retry reserves its new attempt before HTTP. A canonical receipt resolves the outbox. Checkpoint failure after HTTP exposes confirmed admission or remaining uncertainty. A known non-admitted report can be discarded without reusing its sequence. The historical retry path works with the Herdr executable absent.

## Retained evidence and limits

The [collector](pr09-herdr/collect_artifacts.py) retains **142 artifacts** through explicit non-secret allowlists, preserves original hashes and verifies retained bytes. Aggregate SHA-256 is `1836dd6efe7d6b185f2189c439455acb62903bf70d9b4ff47e6e7c99563f5b3e`. Four credential-shaped **synthetic test parameter IDs** are redacted across the source/installed XMLs; original closed reports remain in the temporary qualification directories. Private bearer files are neither collected nor hashed. The public schema and sanitized live fixtures are included; terminal text and personal workspace/provider data are absent.

The command reference is [Herdr observer](../../../docs/herdr-observer.md); source registration, capability issuance, renewal, revocation and the minimal helper example are in [external observations](../../../docs/external-observations.md). Plugin code would run with the user's local permissions; a scoped Nexus token is not a sandbox for a local plugin. No plugin framework is required or installed here.

This evidence qualifies the stated Windows/local/direct-process observation contract. It does not qualify other Herdr releases, remote/Unix transports, unrecognized wrappers, physical power loss, personal service lifecycle, real provider inference, native-client M1/M2, external-attention UI or the joint PR-10 campaign. The fixed R3 tasks and scenarios remain unchanged.

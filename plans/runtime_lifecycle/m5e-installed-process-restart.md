# M5e installed Connector process restart

The M5 prelease startup refusal replay was exercised with three locally built wheels installed in one disposable virtual environment. The Nexus and Connector dependency metadata both require Core 0.0.12. The installed package files were compared byte for byte with the wheels: Nexus 0.3.1 (549 files, SHA-256 `d924055e4cd97a06abae256e1e7843e5033945ca84615849179647ba2e0609b3`), Core 0.0.12 (162 files, `f8ee577c9a869b21d828b89e681d75f6e534b79a04d3e4351a1474169a3f29d4`), and Connector 0.0.10 (100 files, `6f3d5ce354b596e4cee82727dfab3782ad3584b96e354731111020ad998cdf71`). The Nexus wheel included a fresh frontend build. No global installation was changed.

An independent local Connector process failed candidate discovery and paused immediately after committing the startup refusal binding, before releasing capacity or publishing the terminal receipt. The test killed that process, restarted a new process against the same durable state, and verified a new PID and control generation. The original opening received one terminal `PREPARATION_FAILED` receipt with `possible_effect=false`; its session closed, its delivery became `FAILED_FINAL`, and its exact capacity reservation was released. No native open/send occurred for that opening. A subsequent handoff reached `SUBMITTED` with exactly one native open/send, without manual reconciliation.

The Windows test fixture initially launched the virtual environment's `python.exe` redirector and killed its PID instead of the interpreter holding the journal and control link. It now launches `sys._base_executable` where available and asserts the worker-reported PID matches the child PID. The corrected installed process-death case passed alone and within the final integrated run.

Installed validation: Core codec 11 passed; Connector transport/publication/preopen 60 passed; Nexus authenticated prelease, candidate-bind recovery, and actual process-death replay 3 passed (0 failed, 0 skipped). These are disposable local Connector tests, not a physical remote-host or real UI gate. M5 remains in progress: storage/forgery matrix, uncertain-effect startup, per-binding containment, differential reconnect/revoke/reset, load and the major UI-B campaign remain.

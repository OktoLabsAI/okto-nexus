# M7l — Real Pi UI embedded pool and deadline comparison

Date: 2026-10-18 UTC. This is partial UI-B evidence from a disposable installed Nexus 0.3.1 fixture on `127.0.0.1:8204`. The Nexus wheel SHA-256 was `a98b2ee35f18d04360306da2291f5a839bf13e9974179d48d4ccb7ab09e5727a`, with the vendored Core 0.0.12 wheel SHA-256 `55b58a13f7112e63a44a08efb787ca5e43128f4d090fd639a7a9b307e5e43ecd`. The global Nexus at port 8202 and the Connector remained stopped.

In Agents > Connections, a new `m5j-pi-embedded` agent was registered through the UI, bound to the existing disposable M6D workspace and the verified local Pi 0.87.1 installation. Its one-shot policy matched the Connector sample M7k: maximum 2 parallel instances, 1 preinitialized, queue capacity 1, and 5 seconds to start. The connection test received a real model response and closed its test session. The Agents card showed 1/2 available before delivery.

Three prepared Meta-harness tabs sent private messages to that agent within about 1.3 seconds, each instructing Pi to wait 30 seconds and return a distinct marker. All three UI sends were accepted. The warm call started 1.432 seconds after enqueue, returned exactly `M5J_C_OK`, and its message showed 1/1 ACK. The other two calls were terminal `ONE_SHOT_START_TIMEOUT`, with `execution_started=false`, `possible_effect=false`, and `retry_safe=true`; both errors appeared in Meta-harness. The first failed 5.822 seconds after enqueue. The other entered cold admission just before its queue deadline and failed 20.235 seconds after enqueue; it did not run a native turn. The cold opening later became the replacement warm slot. Agents showed 1/2 available again.

Compared with M7k, the result class is equivalent: one successful warm turn, two caller-visible no-effect failures, no execution of expired calls, and pool replenishment. The exact error split differs: M7k observed one start timeout and one queue expiry, while this run admitted the queued call before its deadline and therefore observed two start timeouts. This timing-sensitive sample does not prove a queue-expiry path for embedded, a latency distribution, or the M5j broadcast-handoff recovery itself. Those remain within the existing UI-B gate.

Evidence: the saved Meta-harness screenshot is `output/playwright/m5j-embedded-pi-results.png`; the disposable database has the three `one_shot_calls` and slot transitions. The fixture recorded `shutdown_drained` with empty resources/error codes and `lifespan_finished`; port 8204 stopped listening. No global process was started.

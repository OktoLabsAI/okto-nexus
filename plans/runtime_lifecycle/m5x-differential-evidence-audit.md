# M5x: fixed differential acceptance audit

Date: 2026-10-18. This audit uses the five M5 acceptance cases already defined in `plan.md`. It does not add a new gate or treat a loopback Connector as a physical remote host.

| Required case | Embedded and local Connector evidence | Result |
| --- | --- | --- |
| Retransmission after an uncertain native action | The same parameterized `test_core_native_actions.py` case runs both bridges. Injected response loss after the canonical `handoff.claim` commit returns `OUTCOME_UNKNOWN`; replay with the same operation key yields one claim and one canonical effect. All 18 bridge variants passed from the installed Nexus wheel. | Equivalent canonical effect and replay behavior at the bridge boundary. |
| Receipt loss | Installed `test_lost_receipt_persistence_never_reopens_operation` rejects the Server's embedded receipt insert after one native open. Two installed `test_restart_recovers_historical_receipt_without_provider` variants restore the missing terminal receipt after an embedded restart without reopening the native process. Connector WebSocket cases inject a failed receipt request before commit and a lost ACK after commit; publication recovery retains one native open. | Same durable no-replay/recovery outcome for a missing canonical receipt. The Connector fault test uses a real loopback WebSocket but keeps its daemon in the test process. |
| Revocation | The same parameterized bridge suite rejects the revoked capability and lease on both routes. Installed M5s automated checks and real UI M5u show both agent types become unavailable while siblings remain usable. | Equivalent refusal and isolation at the tested boundaries. |
| Reconnect | Real Pi on a separate local Connector returned an exact Meta-harness response after the daemon rejoined in M5t. Embedded Pi returned an exact response in the same UI fixture. M5m covered creation of another embedded agent while Connector reconciliation was active; M8a covered Connector rejoin after a preserve reset and Nexus restart. | Real local route availability and isolation verified; no physical remote-host claim. |
| Preserve-agents reset | M5v reset an active embedded Pi through the installed UI and delivered again. M5w reset active embedded and Connector Pi sessions in the same disposable Nexus home, preserved agent/workspace/binding configuration, then delivered exact replies through both routes. | Equivalent configuration preservation and fresh delivery verified through the UI. |

Installed-wheel versions were Nexus 0.3.1, Connector 0.0.10 and Core 0.0.12. All runs used `-o pythonpath=` to disable pytest's source import path. The bridge run completed **18 passed**; selected receipt failures completed **3 passed, 53 deselected**; embedded cold recovery completed **2 passed, 28 deselected**. An initial source-path run also passed but is not used as installed evidence.

The fixed M5 outcome invariants now have evidence on both routes. The remaining operational comparison already required by M5 is a receipt-loss/recovery run with the Connector daemon in a **separate process**, matched to the embedded fault scenario; the current WebSocket test keeps the daemon in-process. M5 remains in progress until that process-boundary case is verified. The global Nexus was not started for this audit.

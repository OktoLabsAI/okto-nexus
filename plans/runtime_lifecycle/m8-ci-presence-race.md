Run [39421464096](https://github.com/OktoLabsAI/okto-nexus/actions/runs/39421464096) on `d80e766` passed the previously timed-out Windows 3.12 shard 0. Windows 3.11 shard 0 reported one failure in `test_graph_and_agent_presence_follow_local_connection[DISCONNECTED-offline]`: its `agent_list` result was Offline, while a separate subsequent `agent_get` result was Stale. The test directly changed the live embedded executor's database `control_state` while its owner continued reconciling. The two results can therefore represent different committed connection states; the failed equality did not establish an incorrect individual projection.

The fixture now writes its intended control state immediately before each Graph, Agents, `agent_list`, and `agent_get` read. It accepts the result only if that state remained unchanged through the read, retrying a bounded eight times if the live owner reconciled concurrently. It still asserts the exact expected presence and local connection details for every endpoint, including the case where a recently seen agent remains Offline when its runtime is disconnected. All three parameterized cases passed twice on the local Windows source tree. Product, Core and Connector code were unchanged. The run finished with 22 passing jobs, this Windows failure and a separate Ubuntu timeout documented in [m8-ci-claude-teardown.md](m8-ci-claude-teardown.md).

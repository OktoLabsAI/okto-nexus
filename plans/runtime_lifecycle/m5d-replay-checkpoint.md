# M5d startup refusal replay across control generations

A prelease startup refusal is now recoverable after its original control connection is replaced. The Connector persists the original refusal association before release, then uses the Core journal's no-effect CAS, absence of a native session claim and exact owned-slot/capacity release to construct a report on the new authenticated channel. The original receipt/source remain unchanged. The Server accepts the replacement only while that executor is `RECOVERING`, checks the original pending dispatch and physical release in the same receipt transaction, and acknowledges a duplicate terminal receipt idempotently. Reconciliation recognizes only the specific startup sessions already acknowledged by the Server; it does not scan unbounded historical sessions or invent native claims.

Core commit `99bdd00` on `feature/v0.0.12`; Connector commit `dca2cc7` on `feature/v0.0.10`.

Separate-process local Connector cases exercised a candidate discovery failure with (1) no cut, (2) lost local publication commit acknowledgement immediately after binding, (3) lost acknowledgement after durable report storage, and (4) lost Server acceptance acknowledgement. Each qualified cut eventually delivered the original terminal `PREPARATION_FAILED` caller result, released the matching capacity, restored a ready control connection and delivered a later handoff without manual repair. The post-lease preparation path also passed. The first binding-cut attempt exposed a real distinction: the owned slot was held by the capacity reservation rather than the operation ID. Recovery now releases it through the capacity ledger and verifies no slot remains. One rerun timed out in the test's initial Connector readiness before fault injection under machine load; the same cut then passed when startup completed. The initial lost-ACK assertion was corrected to await the actual generation transition rather than observing the Server receipt before the simulated ACK loss.

Core's focused codec tests passed (11); Connector transport/publication tests passed (60). The Server's focused authenticated prelease test verifies a foreign channel cannot publish the same report. This is source and separate-process validation, not installed-wheel or real Nexus UI qualification. The global installation remains untouched. M5 still requires uncertain-effect startup, storage/forgery matrix, broader per-binding isolation, reconnect/revoke/reset and load gates, followed by the major UI-B campaign.

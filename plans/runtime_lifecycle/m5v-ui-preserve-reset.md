# M5v: preserve-agents reset through the installed UI

The first reset attempt used a restored disposable M6D Server home after the M5u revocation run. Its separate Connector journal had advanced beyond the restored Server generation and refused with `STALE_GENERATION`. Settings > Storage > Reset database, with **Preserve agents, API keys and connection settings** checked, returned: "Reset could not confirm that remote executions stopped. No history or connection configuration was deleted." Read-only counts were unchanged: 7 agents, 1 workspace, 6 execution bindings, 127 execution sessions, 284 messages and deliveries, 4 handoffs, 290 events. This is a safe refusal under an intentionally inconsistent test snapshot, not a successful remote reset or a production-environment failure.

The embedded path was then tested in a new isolated home at `127.0.0.1:8204`, installed Nexus 0.3.1/Core 0.0.12, real Pi 0.87.1. Through Agents, the operator created `m5v-pi` with Worker permissions, workspace M5V, a local Pi connection, and passed the real connection test. Agents showed Online. Meta-harness received exact `M5V_BEFORE_RESET_OK` with 1/1 ACK; the store had one `READY` / `ACTIVE` execution session. Before reset, the store held 2 agents, 1 workspace, 1 binding, 1 execution session, 3 messages and deliveries, and 3 events.

With the preserve checkbox checked, the operator confirmed Reset database in the UI. It completed with `pending=false`, `kept_agents=true`, and deleted the active execution session and operational history. Immediately after reset, read-only counts were 2 agents, 1 workspace, 1 binding, 0 execution sessions, 0 messages/deliveries/events. Agents showed `m5v-pi` Online without reconfiguration. A new Meta-harness message returned exact `M5V_AFTER_RESET_OK`, 1/1 ACK, `read` delivery and `NATIVE_ACCEPTED`; a new `READY` / `ACTIVE` session was created. This verifies preservation of the embedded connection and automatic re-opening after reset with a real harness.

The real Connector path still needs a paired reset run from a fresh, consistent Server/Connector state. Installed automated reset/revocation slices for that transport passed in M5s. The browser and isolated Nexus process tree were stopped; port 8204 and the global listener were left closed.

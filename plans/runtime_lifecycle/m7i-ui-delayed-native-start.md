# M7i — Real UI handoff beyond the former 60-second cap

Date: 2026-10-18 UTC. This is partial UI-B evidence, not a latency distribution.

The disposable installed Nexus 0.3.1 fixture on `127.0.0.1:8204` used the installed Connector 0.0.10 daemon, Core 0.0.12 and real Pi 0.87.1. The Pi one-shot policy was maximum 1 parallel, 0 warm, 1 queued, with the inherited 300-second wait-to-start budget and automatic broadcast claims. The global Nexus stayed stopped. All sends below were made through Meta-harness; timing and receipt inspection was read-only.

The first experiment injected a 75-second wait **between Connector binding and Core.open**. The broadcast handoff was claimed, but a lease renewal made the captured context stale during this artificial gap. The delayed `Core.open` failed immediately with `STALE_GENERATION`; replacement-owner recovery durably recorded `PRE_EXECUTION_FENCED` for `runtime.open`, with `possible_effect=false` and `retry_safe=true`. The one-shot call became FAILED before execution started. The original operator received a **Nexus one-shot error** message with that code and retry safety, and Handoffs showed **Execution failed**. The handoff remained CLAIMED for operator disposition; it was cancelled through Handoffs in this disposable fixture. This run is not a successful long native startup, and it did not create a Pi process.

The second experiment moved the same 75-second wait **inside the Pi native startup**, after Core had admitted the opening. At 02:33:22 UTC, Meta-harness sent broadcast handoff `M7J delayed native handoff`; Pi auto-claimed it. The Connector trace records `injected.native_start_wait` from 02:34:02.822 UTC to 02:35:17.823 UTC, then real Pi startup and turn execution. Durable `runtime.open` was created at 02:33:26.557 UTC and reached its first SUBMITTED receipt at 02:35:20.709 UTC (**114.152 s**). The turn reached SUCCEEDED at 02:35:42.932 and close at 02:35:44.494 UTC. Meta-harness showed one completed handoff, exact result `M7J_HANDOFF_OK`, **1/1 ack** on the managed request and no alert. This directly exercises a healthy admitted opening beyond the old 60-second immediate deadline while retaining real Pi execution.

The delay is controlled fault injection, not natural Pi latency. The result proves that this installed path can remain admitted past 60 seconds and still finish within the configured 300-second start budget. It does not establish a production latency distribution or guarantee success for every slow environment. The Connector daemon stopped through its CLI; the Nexus fixture recorded `DRAINED`, no resources or error codes, then `lifespan_finished` at 02:36:16 UTC. The browser closed and ports 8202/8204 had no listener. UI-B still needs a real queue deadline, embedded comparison, other harnesses and a wider load distribution.

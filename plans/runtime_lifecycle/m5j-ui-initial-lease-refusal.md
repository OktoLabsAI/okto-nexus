# M5j: real UI initial-lease refusal and handoff reopening

The disposable installed Nexus 0.3.1 fixture at `127.0.0.1:8204` used the current Connector 0.0.10 and native Pi. The operator created the broadcast handoff `hof_c5dfac3d451b486fb57375b56de7558b` in Meta-harness. It was claimed by `m6d-pi` in one-shot mode. Its initial `runtime.open` was denied as `LEASE_REVALIDATION_REQUIRED` before native execution, with an authenticated Core receipt (`possible_effect=false`, `retry_safe=true`). The session and lease became `CLOSED`; the one-shot call and outbox failed without effect. The handoff nevertheless stayed `CLAIMED` because its admitted initial `turn.submit` remained `ACCEPTED` with no dispatch record. The M5j proof view correctly refused to infer safety from that incomplete state.

The initial-lease-refusal receipt path now settles unsent initial turns in the same transaction as closing the session, as the preparation-refusal path already did. A focused integration test inserts the real parent/child operation shape and verifies `RESOLVED_TERMINAL` plus `INITIAL_OPEN_FAILED` after refusal. All 18 relevant source tests passed: eight M5j proof/reopen cases, four initial-refusal cases, and six restart-recovery cases. The restart expectations now distinguish an unproved pre-Core refusal, which stays claimed, from a proved no-effect refusal, which reopens. After installing wheel SHA256 `d8f2109cac3eaee1316ed209c7a19112db14cd1c302b3887da31d30f55a4599c` in the isolated environment and draining/restarting only the disposable fixture, existing startup reconciliation settled the old unsent turn. The scheduler then reopened the handoff, retired the old attempt as `FAILED_NO_EFFECT`, and recorded a 15-second Pi retry cooldown. The Handoffs UI displayed one `Open` handoff with the original title and ID. No duplicate turn or native action was observed. The controlled 75-second pre-Core delay was armed but never reached, so this run does not validate that delay path.

The remote Connector did not regain control after this fixture restart. Its log shows repeated R4 reconciliation cycles ending at the three-attempt limit (`wss_r4.py:167`); the fixture contains 21 older dispatched opening operations in closed sessions. The exact server-side rejection within those cycles has not been isolated. The UI therefore showed `capacity protocol unsupported`, and this run does not claim an eventual Pi completion or the full UI-B gate. The previously published M7i run separately verified a delayed Pi handoff completion. Global Nexus remained stopped throughout.

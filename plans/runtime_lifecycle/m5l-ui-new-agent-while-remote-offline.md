# M5l: new embedded Pi while a remote Connector is unavailable

The disposable installed Nexus 0.3.1 fixture at `127.0.0.1:8204` was resumed with the local embedded owner active and its separate Connector stopped. In Agents, `m6d-pi` was Remote / Offline. Through the Nexus UI, the operator created `m5l-pi-new` with the Worker preset and configured a local Pi 0.87.1 connection in the existing M6D workspace. The wizard reused the previously registered local workspace folder, verified the Pi installation and completed a real harness connection test. Agents then showed the new local agent Online while `m6d-pi` remained Offline.

Meta-harness sent `msg_c305d071d8674c178339a2e62eabe4d0` to the new local agent at 04:35:21 UTC. The native Pi returned `msg_a8aab5d1f39646a48aa9dc75dad53925` with exact body `M5L_LOCAL_OK`; the UI showed ACK 1/1 and the durable delivery was read. The Connector was then started with the fixture's approved file-vault backend. Its first control attempt became `CONTROL_READY`, with zero consecutive failures; CLI connection status was `CONNECTED`, and Agents showed both the remote and the new local Pi Online. Meta-harness then sent `msg_119c03307cb34193a3451a8580a9a4c6` to the remote Pi at 04:37:45 UTC. The native remote Pi returned `msg_623051113c1149009daf569f9b447955` with exact body `M5L_REMOTE_OK`, again with ACK 1/1. Both input deliveries were read, and the Connector remained `CONTROL_READY` after the response.

The isolated installed Nexus wheel passed all six `test_initial_refusal_restart.py` crash-boundary cases. The installed Connector wheel passed all 15 `test_r4_denied_operations.py` cases. These tests cover matching initial-refusal invariants but do not constitute one end-to-end differential script across the two host modes.

This real UI run proves that agent creation and local execution can progress while a separate remote Connector is unavailable, and that the remote reconnects without operator repair. The remote was deliberately stopped and shown Offline, not held in an active reconciliation while the new agent was created. The stricter UI-B concurrency case of creation *during* a long-running reconciliation remains open. The fixture and Connector were drained and stopped; the global Nexus listener at 8202 was untouched.

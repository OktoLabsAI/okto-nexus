# M5h physical capacity identity rejection

The separate local Connector process made a real handoff capacity admission, failed candidate discovery before an initial lease, and persisted its original no-effect refusal. At the publication seam the test sent one protocol-valid in-band report with a different `capacity.reservation_id` and a distinct request ID. The Server deferred it: the original session remained `OPEN_PENDING` and no opening receipt was committed. After the test released the publication gate, the Connector sent its unchanged durable report; the Server committed the original terminal refusal, released the matching capacity and accepted a subsequent handoff with one native open/send. The control connection stayed ready during the forged attempt.

The focused test passed against the installed Nexus 0.3.1, Core 0.0.12 and Connector 0.0.10 wheels from M5e (1 passed, 9 deselected). Its wall time was 229.73 seconds on the shared Windows machine; no latency claim follows from this fault-injection run. The fixture only modifies its own Connector child and never the global installation. This covers reservation identity mismatch, not every capacity field, malicious physical host behavior or a real remote machine. M5 remains in progress.

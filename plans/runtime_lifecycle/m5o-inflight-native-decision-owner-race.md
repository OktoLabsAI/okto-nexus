# M5o: in-flight native decision versus owner replacement

Two deterministic fault-boundary tests hold a real Core native decision callback after the decision has been admitted. They cover approval and input decisions. The embedded test then fails its current owner; it runs with Pi, Claude and Codex adapters. In each case, the old owner remains in place while the callback is held; after release it drains, a successor takes ownership, the decision has `SUBMITTED` receipt, and exactly one native reply occurred. Reposting the same decision after replacement returns the original operation, with no second effect or dispatch attempt.

The Connector test uses the actual local loopback WebSocket and automatic daemon control, then closes the old link while its native approval callback is held. Its five-second lease expires before the callback is released. The old execution remains unavailable and its native process is not treated as stopped while the callback can still produce an effect. After release, the Connector reconnects with a higher connection generation; the decision has `SUBMITTED` receipt, the native process is stopped, the same decision replay resolves to its original operation, and the physical reply count is one. The dispatch outbox has no attempt above one.

The eight cases passed against source packages in 120.39 seconds. The six embedded cases and the two remote cases also passed separately against the isolated installed wheels. No production code changed, and no global Nexus process was started. This closes the **native approval/input decision versus owner replacement** slice; other native-action races, per-binding containment and the full M5 differential matrix remain open.

# M5m: create an embedded Pi during active remote reconciliation

The disposable installed Nexus 0.3.1 fixture ran at `127.0.0.1:8204` with a separate local Connector process. A controlled, local `reconcile.report` refusal was armed on that Connector. The Connector stayed alive and attempted reconciliation repeatedly: its CLI reported `RECOVERING` with 3, then 15 consecutive failures, while Agents showed the remote `m6d-pi` Offline. This was an active recovery failure, not a stopped process.

During that recovery, the operator used the Nexus Agents UI to create `m5m-pi-new` with the Worker preset and configure local Pi 0.87.1 in the existing M6D workspace. The wizard reused the registered local workspace path, the real connection test passed, and Agents showed the new embedded Pi Online while the remote stayed Offline. Meta-harness sent `msg_0568965d9468477bb4c3f9f6bf3853e0` at 04:54:54 UTC. The native embedded Pi returned `msg_2e1a06a21e474eb4be44ad98dd9fc7de` with exact body `M5M_LOCAL_OK`; the UI showed ACK 1/1, and the durable delivery was read with `NATIVE_ACCEPTED` outbox acknowledgement.

After the controlled refusal was removed, the Connector became `CONTROL_READY`, its remote agent `CONNECTED`, without restarting Nexus or Connector. Meta-harness sent `msg_0b7f067b7dd14ae6a9913e0b1d7ef384` to that remote agent at 04:59:03 UTC. A subsequent inventory publication lost its HTTP outcome; the Connector reconnected automatically at 05:00:01 UTC. The pending delivery was read at 05:01:15 UTC and the native remote Pi returned `msg_8cda77e865ae43aa8ec3e829900704be` with exact body `M5M_REMOTE_OK` at 05:01:16 UTC. Its outbox reached `NATIVE_ACCEPTED`, and the UI showed ACK 1/1. This verifies that a transient control interruption did not discard or duplicate the queued message. The remote response latency in this fault-injected run is not a normal-performance measurement.

This closes the UI-B slice of creating and executing a new embedded agent while a separate Connector actively fails reconciliation, and then recovering the remote agent without operator action. It does not complete the broader M5 differential matrix or UI-B load/latency distribution. The controlled fault existed only in an ignored local test bootstrap. The global Nexus listener at 8202 was untouched.

The browser and Connector were stopped. The fixture reported `DRAINED` with no resources or errors, finished its lifespan, and ports 8202, 8204 and 60062 had no listeners.

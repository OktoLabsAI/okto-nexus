## Supported owner actions, not SQL authority

The current API already exposes `DELETE /api/v1/harness/grants/{grant_id}` in
`adapters/inbound/http/routes.py`. It calls `RuntimeAccessService.revoke`, which
revokes the grant and invokes `execution_revocation.invalidate_sessions` for its
real leases: lease state/status and session capabilities are invalidated without
claiming that a process exited. Alternatively, the existing CAS endpoint disable
path (`PATCH /api/v1/harness/endpoints/{id}`) is exercised by an older QuickConnect
test. These are concrete future H07 owner paths; neither was used by the new
supplement's SQL negative. A same-name successor must still be created through
actual supported setup/open APIs, never cloned leases/grants or a renamed ID.

The shipped UI setting is localStorage `okto-nexus-home-operational`, changed
through Settings behind `mayLeavePanel`; App selects OperationalHome or HomeView
and negotiates v2 from server capabilities. S3 must exercise this setting, not
rewrite `/info` or confuse a QuickConnect environment flag with presentation.

No complete scenario is promoted by this review. Provider/native-topology,
application acknowledgement, accessibility, human/default approval and the
unchanged performance threshold remain separate gates.
